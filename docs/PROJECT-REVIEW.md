## 设计策略

1. **先建立视觉秩序。** 暖纸背景 `#f5f3ed`，墨色 `#302f29`，朱红 `#a74933`，鼠尾草绿；中文衬线标题与系统无衬线正文形成层次。克制使用圆角和阴影。
2. **让棋盘承担视觉主角。** 首页采用矢量棋子与透视棋盘，棋类卡片用同一套素材绘制缩略棋盘。对局页把棋盘与设置、状态、棋谱并置。
3. **把美感延续到操作。** 落点提示、最后一手标记、回合文案、重开确认与存档提示都有统一视觉规则。
4. **按用户追加要求提供变化。** 2D / 3D、倾角、轻微旋转，以及木纹、地形、世界地图三套皮肤；主题地图不改变原棋类走法。保留格线和落点识别。
5. **移动端重新排布。** 导航在手机移至底部；大厅卡片两列，对局页棋盘优先，控制区后置。外观偏好在所有棋类间共享。

## 首版取舍

先提供可玩的四种棋，完成一局、悔棋、保存、恢复与导出。不放不可用的联机按钮、虚构在线人数或排行榜。使用静态 ESM 模块，避免在产品尚未确认时引入账户与后端运维。国际象棋复用经过维护的规则库，其余规则与 AI 在独立模块内实现。

首版每日题固定为编号 001，不声称题库已每日更新。首版使用 CSS 三维变换；根据追加反馈，现已升级为 WebGL 三维模型，支持环绕镜头、材质、实时阴影、吃子冲击、走子动画和获胜彩蛋。地图仍不改变经典棋类规则。

## 后续修改建议（按优先级）

### P1：增加中国象棋与围棋

各自使用独立规则模块，统一接口为创建棋局、合法走法、应用走法、撤销、终局判断、序列化。中国象棋先覆盖将帅照面与将军判定；围棋需明确规则、提子、劫争、停着及计分方式。不要只画出棋盘就宣称可玩。

### P2：增加真正的联网对战

服务端作为局面唯一裁决者，用 WebSocket 同步动作、版本号、房间状态及断线恢复；客户端只提交走法意图。匹配、邀请链接、旁观与计时逐步接入。账号与跨端棋谱同步在此阶段加入。

### P3：提升棋力与复盘

国际象棋通过 Web Worker 接入引擎，并按部署方式审查其许可证与分发要求。其他棋类分级难度；搜索放到 Worker，避免阻塞操作。先建设可以逐手前进/后退的复盘，再增加局面评价。

### P4：地图战略棋模式

当前地图为棋盘外观。若需要“地形影响走法”“世界征服”等玩法，应该作为单独棋种定义规则：格点/区域邻接、地形通行、占领、补给、回合与胜负。继续复用主题系统，避免让经典棋类规则产生歧义。
